We rebuilt 7.3.0 with the same configuration (7.3.0-kernsight-kasan #2,
gcc 11.4.0 Ubuntu 22.04, KASAN/KCOV, CONFIG_FAIL_SKB_REALLOC=y) and re-ran the
same 42-program sequence that triggered the UAF on the unmodified 7.3.0.

Results:
- unmodified 7.3.0: 1/1, GPF + KASAN slab-use-after-free in
  sctp_unpack_cookie, first report at t=212.7 s.
- reverted 7.3.0: 2/2 runs completed without panic; neither serial log
  contains the KASAN report. Fault injection still fires (failslab, times 0,
  4 messages per run), but it now lands elsewhere in sctp_unpack_cookie
  (stack shows sctp_unpack_cookie+0x68e) and there is no stale-pointer access.

As you noted, this issue requires CONFIG_FAIL_SKB_REALLOC; our tests enable it.

the repository:
